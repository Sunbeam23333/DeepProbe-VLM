# 实验协议：先建立可信基线，再证明新增机制

2026-10-07 release。这里是待执行计划，不是结果表。任何“收益”都必须来自保存的预测、训练日志和硬件记录。

## 当前方法到底做什么

1. 每个视频均匀取 F 帧，经 SigLIP 编码一次。
2. 每帧通过可训练的加权空间池化与 MLP 连接器，压到 G × G 个视觉 token。
3. 视觉前缀与问题一起进入 Ouro 的**原生共享权重循环**。输入预填充阶段，所有视觉和文本状态在每一轮都会更新。
4. 只用最后一轮输出计算答案 token 的交叉熵；全循环反向传播，不在循环之间截断梯度。
5. 推理时不做在线参数更新；逐循环 KV 缓存保持独立。**不是 test-time training，也不是浅层 KV 直接代替深层 KV。**

“视觉编码一次”仅指图像编码器，不意味着语言模型内部的视觉 token 只算一次。当前代码使用标准注意力库，没有自定义 CUDA/PTX 算子。

当前采用因果的“视觉前缀在前、问题在后”顺序：问题/答案状态每轮可读取视觉信息，但视觉前缀看不到后面的提问。因此**当前视觉状态更新不是 query-adaptive**。若研究问题条件化刷新，必须另外设计输入顺序/注意力结构及其对照，不能只改论文描述。

## 必须先跑的实验

| 优先级 | 实验 | 控制条件 | 要回答的问题 |
|---|---|---|---|
| P0 | 20-step pilot、断点续训、cached/no-cache parity | 先 1 卡再 8 卡，小数据集 | 数据、梯度、检查点、NCCL 是否真的可用 |
| P1 | Ouro R=1/2/4 分别训练 | 同数据、视觉前缀、优化步数、seed | 循环深度对视频理解是否有收益 |
| P1 | SmolLM2-1.7B 对照 | 同视觉模块、数据和两阶段训练 | 与普通小模型相比，质量/成本落在哪里 |
| P1 | 视觉编码器冻结 vs 全参数更新 | Ouro R=4，其余相同 | 视觉全参数更新是否必要 |
| P2 | F=4/8/16；G=2/4/8 | 一次只改一个因素 | 时间覆盖和空间分辨率哪个更关键 |
| P2 | 无对齐阶段 vs 有对齐阶段 | 相同总训练预算另做补充 | 对齐是否帮助稳定性，而非仅多看数据 |
| P2 | 逐循环缓存 vs 无缓存 | 同一 checkpoint、相同 greedy decoding | 缓存正确性与真实端到端成本 |
| P2 | H20 vs B300 | 相同输入、batch、dtype、软件记录 | 同一任务在两种硬件上的实测差异 |

SmolLM2 与 Ouro 的预训练语料、参数量、结构、词表和初始指令能力不同，因此这个对比只是**外部参考**，不能证明循环结构的因果优势。主要机制证据来自 Ouro 内部的深度/预算控制。全模型大小也包含视觉编码器和连接器，不要把整个 VLM 标成“只有 1.4B”。

生成配置（只写配置、不启动任务）：

```bash
python scripts/make_ablation_configs.py --output-dir runs/ablation_configs
```

生成器包含重复的默认设置以便逐轴管理；实际运行时去重。三个种子为 17、29、43。主表最终比较应保留至少三次独立训练；初期 pilot 不需要把矩阵全跑完。不能把一个 R=4 检查点在推理时改成 R=1 称为“R=1 从头适配”的结果。每种 R 的对齐/SFT 都应采用相匹配配置，并记录阶段预算。

## 数据和评测

训练首选 LLaVA-Video-178K 的可控子集；按**原始视频 ID**分出验证集，不按问答行随机切分。同源视频及其不同片段必须在同一 split。保留跨阶段、跨数据集的来源 ID，任何祖先训练/调参数据都不得重新出现在最终测试集。详见 [DATASETS.md](DATASETS.md)。

Video-MME：报告总体及 short/medium/long 分组的多选准确率；无字幕实验不和带字幕的官方结果混为一谈。稀疏 8 帧只是成本基线，不能据此声称完整长视频理解能力。

MVBench：按任务类型报告准确率与可评测数量；有许可或媒体缺失的任务明确标为子集，不能直接称完整官方 MVBench。确保 Charades/TVQA 的时间片段模式与媒体匹配。

当前评估器支持多选准确率和开放问答 normalized exact match；后者**不是开放回答语义评分或官方大模型 judge**。不要将二者混成一项主结果。

```bash
python scripts/analysis/summarize.py \
  --predictions runs/ouro_sft/video_mme.jsonl \
  --reference runs/smollm2_sft/video_mme.jsonl \
  --output runs/analysis/paired_video_mme.json
```

该工具要求两组样本、标签、来源、split 完全一致，按来源视频进行成簇 bootstrap，输出配对准确率差与 95% CI。多个问题来自同一个视频时，不能把它们当独立视频计置信区间。按长度、任务分组；报告失败/缺失样本数，不静默删除难样本。

## 系统测量，不猜倍数

- 先固定 F/G/R、文本长度、生成 token 上限、batch、dtype、kernel backend。
- 保存 GPU 型号/数量/驱动/CUDA/PyTorch/依赖版本与模型、数据 SHA。
- 分开报告视频预处理、模型执行与完整请求时间。模型执行包含视觉编码、prefill 和 decode；当前 CLI **尚未分别计量这三个阶段**。
- 当前逐样本延迟是 cold/mixed 描述性记录；`--profile` 会增加额外开销。两者都不能直接标成 warmed serving throughput。
- 正式速度实验应增加固定 warmup、多次重复、显式 CUDA 同步，至少报告中位数/p95 和峰值显存；并同时检查答案质量。训练吞吐与推理延迟分表。
- CUDA 优化要先定位瓶颈，再写算子。稀疏 mask 不等于 GPU 真正少算，跨轮共享权重也不等于跨轮 KV 可直接复用。

预计训练时间只能在 pilot 后计算：`剩余优化步数 × 稳态秒/步 + 验证/保存时间`。不同卡上的数据解码/I/O 瓶颈可能使速度比例完全不同，不承诺 H20/B300 理论倍数。

## 下一步创新分支（未实现）

1. **训练可用的选择性视觉状态刷新**：在循环主干内学习哪些视觉状态要更新，保留稠密参考与退化回退路径；检查不同轮状态和 KV 的一致性，而不是仅在外围筛帧。
2. **可解释的计算预算目标**：在质量约束下控制激活 token × 循环深度的预算。先用期望计算/预算惩罚做可检验假设，再验证其和实测延迟的关系；不先声称新定理或必然加速。
3. **算法与 CUDA 联合设计**：仅当选择性刷新在质量上成立且 profile 证明值得做时，再实现 token compaction、调度和融合。每个算子做数值、梯度、缓存与端到端收益检验。

这些是后续研究假设，而非本次提交已经交付的功能。原生循环 VLM、视觉池化和普通 SFT 本身不宣称首创。新论文主结果应等机制与消融真实完成后再写。
